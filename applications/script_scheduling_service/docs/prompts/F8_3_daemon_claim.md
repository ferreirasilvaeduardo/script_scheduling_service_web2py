## Objetivo
Colocar o agente executor de pé: inicialização fail-fast, claim concorrente seguro, execução, heartbeat, coleta de log, cancelamento, timeout e finalização (somente POSIX).

Em erro ou COMMIT incerto, preserva o mesmo bloco/offset para reconciliação idempotente no ciclo seguinte; `POSSE_PERDIDA` vai para `OWNERSHIP_LOST`, e `LogOffsetInconsistente` interrompe o pump daquele ticket com ERROR, sem retry cego. `REGISTRO_PERDIDO` leva a CRITICAL, `TERMINATE` e saída ≠ 0 (R-11). O instante do último heartbeat confirmado é o `time.monotonic()` capturado **antes** do primeiro `UPDATE` da transação, promovido só no `COMMIT` (CR-008, R-09). O pump roda **depois** do heartbeat, com o orçamento e o rodízio de `log_pump.Rodada` (CR-008, R-11). O instante do último heartbeat confirmado também é registrado, para uso pelo F8.4.

Depois, `script_ativo_homologado`. Qualquer falha dá `PRECHECK_FAILED`, `-4`;
